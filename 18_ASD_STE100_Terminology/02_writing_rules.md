# Writing Rules

## 1 Purpose

This document defines the writing rules for project documentation.

## 2 Sentence Rules

- Maximum 25 words per sentence
- One instruction per sentence
- Use active voice: "Run the command" not "The command should be run"
- Use imperative mood for procedures: "Record the state"
- Do not use `shall` — use `must` for requirements, `will` for future
- Do not use `please` — use direct instruction
- Do not use `utilize` — use `use`
- Do not use `commence` — use `start`
- Do not use `prior to` — use `before`
- Do not use `in order to` — use `to`
- Do not use `furthermore` — use `also` or `and`
- Do not use `very` — omit or use precise qualifier
- Do not use `easily` — omit
- Do not use `incorrect` — use `wrong` or `faulty`

## 3 Warning Rules

- State the exact hazard: "Disabling this package causes boot failure"
- State the consequence: "The watch will not start"
- State the recovery: "Factory reset from recovery menu is required"
- Do not write "Be careful" or "Use caution"

## 4 Formatting Rules

- Use tables for structured data
- Define abbreviations on first use
- Use code blocks for commands and file paths
- Use relative paths from repo root
- No generated content blocks (all content authored)

## 5 Cross-Reference Rules

- Reference other docs by path from repo root
- External URLs in `19_References/01_references.md`
- Do not duplicate content — reference instead
